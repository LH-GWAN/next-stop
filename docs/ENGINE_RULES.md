# 추천 엔진 규칙

코드: `web/lib/engine/` (설정값은 `config.ts`), 테스트: `web/lib/engine/__tests__/engine.test.ts`

## 1. 시간 조건

```
여유 B  = max(10, ceil(0.2 × T))          T = 남은 시간(분)
이동 go = 경로 이동시간 (+ 차량이면 주차 5분)
total   = go + 이용 + 복귀 + B ≤ T
```

| T | 30 | 50 | 60 | 90 | 120 |
|---|---|---|---|---|---|
| B | 10 | 10 | 12 | 18 | 24 |

- 서식4 예시(50분 = 이동 10 + 이용 20 + 복귀 10 + 여유 10)는 정확히 통과한다(테스트).
- 화면의 `여유`는 `T - (이동 + 이용 + 복귀)`로, 항상 B 이상이다.
- 결과가 없으면, 영업 조건은 맞지만 시간이 모자란 곳 중 필요한 T가 가장 작은 곳을 `N분이면 ○○ 가능`으로 보여준다. 이때 T가 늘면 B도 늘어나는 점을 반영한다(예: 필요한 시간이 41분이면 51분이 아니라 52분).

## 2. 영업 조건

도착 `a = now + go`, 떠나는 시각 `d = a + 이용`.

1. `parse_status`가 `ok`가 아니면 추천하지 않는다(`영업정보 확인 필요`로 집계).
2. 쉬는 날이 아니어야 한다: 정기 휴무 요일, 명절(설·추석 당일 또는 연휴), 공휴일, 1월 1일 같은 날짜, 매월 n째 주 요일.
   - `공휴일인 경우 다음 날 휴무`: 휴무 요일이 공휴일이면 그날은 열고 다음 날 쉰다.
   - 공휴일 판정은 Python `holidays` 패키지(KR)로 만든 표를 쓴다(대체공휴일 포함).
3. `a`가 영업 구간 안에 있고 `d ≤ 마감`이어야 한다. 브레이크 타임은 구간에서 뺀다.
4. 마지막 입장·주문 시각이 있으면 `a ≤ 마지막 입장`이어야 한다. `마감 N시간 전 입장마감`도 반영한다.
5. 익일 새벽까지 여는 곳(예: 17:00~익일 01:00)은 전날 영업으로도 판정한다.
6. 계절별 시간(하절기·동절기)은 월 범위가 적힌 경우에만 쓴다. 월 범위가 없으면 `partial`로 두어 추천하지 않는다.

## 3. 후보 고르기

조건을 통과한 곳을 점수순으로 최대 3곳 보여준다. 1위를 `추천`으로 표시한다. 동점이면 `id` 순(같은 입력 → 같은 결과).

| 항목 | 가중치 | 근거 |
|---|---|---|
| 관심 항목 일치 | 3 | 입력값 |
| 체험·문화 | 2 | 데이터랩: 양평군 외지인 관광소비 중 여가서비스업 4.8% |
| 가까울수록 `1 - 이동/T` | 2 | 이동이 짧을수록 불확실성이 작다 |
| 영업정보 직접 확인 | 1 | `verified.csv` |

관심 항목을 골랐는데 해당 범주에 갈 수 있는 곳이 없으면 전체에서 고르고 화면에 알린다.

| 관심 항목 | 범주 |
|---|---|
| 먹거리·카페 | cafe, food |
| 쇼핑 | shopping |
| 체험·문화 | experience, culture, sight |

## 4. 가정값 (실측 아님)

`data/config/dwell_minutes.yaml`: 카페 25, 음식점 40, 쇼핑 15, 체험 30, 문화시설 30, 관광지 20분.
문화시설은 TourAPI `spendtime`(관람 소요시간)이 한 값으로 해석되면 그 값을, `verified.csv`에 값이 있으면 그 값을 먼저 쓴다.
화면에는 `약`을 붙이고 `유형별 평균 가정값`이라고 표시한다.

## 5. 속성 테스트

샘플 데이터에 대해 무작위 입력 1,000개(T 20~120, 도보·차량, 관심 항목 조합, 60일 범위의 시각)로 다음을 확인한다.

- 추천된 모든 곳: `이동 + 이용 + 복귀 + 여유 ≤ T`
- `여유(slack) ≥ B`
- `parse_status == "ok"`
- 떠나는 시각 ≤ 마감 시각
